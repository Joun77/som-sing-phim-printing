Master Prompt: ระบบจัดการโรงพิมพ์ (Printing Shop Management System)Role: คุณคือ Expert Full-Stack Developer และ System Architect ช่วยพัฒนาระบบบริหารจัดการโรงพิมพ์ (Backend: Golang, Frontend: React) โดยเน้นความเสถียร ความถูกต้องของสูตรคำนวณราคา และกระบวนการผลิตที่เป็นมาตรฐาน1. Tech Stack & ArchitectureBackend: Golang (Gin หรือ Fiber Framework)Frontend: React (Vite, React Query สำหรับ Server State, TailwindCSS)Database: PostgreSQL หรือ MySQL (Relational Database)Document Engine: PDF Generator ใน Golang สำหรับออกใบเสนอราคา (Quotation) และใบส่งสินค้า (Delivery Note)2. ระบบอัตราแลกเปลี่ยน (Multi-Currency & Daily Exchange Rates)Base Currency: สกุลเงินหลักของระบบคือ LAK (กีบ) ข้อมูลต้นทุนวัตถุดิบและฐานข้อมูลจะอ้างอิงเป็น LAKDaily Exchange Rates Table: มีตาราง currency_rates เก็บเรทประจำวัน (เช่น LAK -> THB, LAK -> USD) โดยเปิดให้แอดมินกรอกอัปเดตเรทเงินได้ทุกวันCurrency Conversion Logic:เมื่อเลือกการสร้างออเดอร์ในสกุลเงินอื่น (เช่น THB) ระบบ Backend จะดึงเรทล่าสุดของวันนั้นมาแปลงราคาสุทธิให้อัตโนมัติExchange Rate Snapshot: ในตาราง orders ต้องบันทึก exchange_rate ณ วันที่ออกเอกสารไว้เสมอ เพื่อให้ยอดเงินย้อนหลังตรงกับความเป็นจริง แม้เรทเงินในอนาคตจะเปลี่ยนไป3. ระบบคำนวณราคาและต้นทุน (Pricing Engine - CRITICAL)ข้อกำหนดสำคัญ: การคำนวณราคาทั้งหมด ต้องทำที่ Golang เท่านั้น ห้ามคำนวณราคาสุทธิที่ React (Frontend)3.1 สูตรคำนวณกระดาษ (Paper Cost)$$\text{Cost}_{\text{paper}} = \left( \frac{\text{ราคาซื้อยกรีม/แพ็ค}}{\text{จำนวนแผ่นในแพ็ค}} \times \text{จำนวนแผ่นที่ใช้จริง} \right) \times (1 + \text{Wastage}\%)$$รองรับการคิดความเผื่อเสีย (Wastage / Spoilage %) ตอนตั้งเครื่องพิมพ์3.2 สูตรคำนวณหมึกพิมพ์ (Ink & Toner Cost)รองรับทั้งเครื่องพิมพ์ Laser (Toner) และ Inkjet:Input จากหน้าบ้าน: รับค่า % Ink Coverage (เช่น 5% สำหรับข้อความทั่วไป, 30% สำหรับรูปภาพ, 80% สำหรับภาพเต็มแผ่น) และจำนวนหน้าLogic หลังบ้าน:$$\text{Page Yield Adjusted} = \text{Standard Yield (at 5\%)} \times \left( \frac{5\%}{\text{Input Coverage\%}} \right)$$$$\text{Cost}_{\text{ink}} = \left( \frac{\text{ราคาตุก/ตลับหมึก}}{\text{Page Yield Adjusted}} \right) \times \text{จำนวนหน้าที่พิมพ์}$$3.3 ค่าเข้าเล่มและอุปกรณ์ประกอบ (Binding & Hardware Cost)อุปกรณ์ที่นับเป็นชิ้น (เช่น สันกระดูกงู, ปกพลาสติก):$$\text{Cost}_{\text{binding}} = \left(\frac{\text{ราคาซื้อเหมา}}{\text{จำนวนในแพ็ค}}\right) \times \text{จำนวนที่ใช้} + \text{Fixed Setup Fee}$$3.4 ค่าบริการคัสตอม & ค่าแรง (Custom Services & Labor Fee)รองรับการเพิ่มรายการคัสตอมในแต่ละ Order Item (เช่น ค่าตัดกระดาษ, ค่าเจาะรู, ค่าพับ, ค่าแรงพิเศษ)สามารถใส่เป็นราคาต่อหน่วยหรือราคาเหมาเหมา (Flat Rate) ได้3.5 Pricing Snapshotในตาราง order_items ต้องบันทึก unit_cost_snapshot และ unit_price_snapshot ณ วันที่รับออเดอร์เสมอ เพื่อป้องกันราคาในบิลเก่าเปลี่ยนเมื่อต้นทุน Master Table มีการอัปเดต4. โครงสร้างผู้ใช้งาน (RBAC - Role-Based Access Control)admin: เข้าถึงได้ทุกระบบ (ดูต้นทุน, กำไร, รายงานการเงิน, ตั้งค่าสูตรและเรทเงิน)sales: รับออเดอร์, ดูราคาขายลูกค้า, แนบ Link Google Drive (ห้ามเห็นต้นทุน/กำไร)production: ดูคิวงานพิมพ์, อัปเดตสถานะการผลิต, เปิดดูไฟล์ Google Drive (ห้ามเห็นข้อมูลราคาหรือการเงินทุกชนิด)5. Workflow ของออเดอร์ (Order Workflow)DRAFT: สร้างออเดอร์ (ระบุสเปก, เพิ่ม Link Google Drive)WAITING_DEPOSIT: รอลูกค้าโอนมัดจำ (สามารถระบุ % หรือจำนวนเงินมัดจำได้)PREPRESS_CHECK: ช่างตรวจสอบไฟล์งานจาก Google DriveWAITING_APPROVAL: ส่งแบบให้ลูกค้ายืนยัน (รอคำตอบ)READY_TO_PRINT: ลูกค้าอนุมัติแบบแล้ว -> ระบบทำการ Reserve / จองสต๊อกวัตถุดิบIN_PRODUCTION: กำลังพิมพ์ / ตัด / เข้าเล่ม (ระบุเครื่องพิมพ์ที่ใช้งาน)COMPLETED: ผลิตเสร็จสิ้น -> บันทึกของเสีย (Wastage) และทำ Actual Stock DeductionDELIVERED: จัดส่งสำเร็จ / รับชำระเงินครบถ้วน6. ลำดับการพัฒนา (Development Phases)Phase 1: Database Schema & Auth & Multi-Currencyออกแบบ SQL Schema (Users, Materials, Orders, Order_Items, Currency_Rates, Production_Jobs)ทำระบบ Login/JWT Middleware พร้อม RBACทำระบบจัดการเรทเงินประจำวันPhase 2: Product & Pricing Engine (Core Focus)เขียน Golang API สำหรับสูตรคำนวณราคา (กระดาษ, หมึก Laser/Inkjet, เข้าเล่ม, ค่าบริการคัสตอม)ทำ Unit Test ทดสอบความถูกต้องของสูตรคำนวณราคาPhase 3: Order Management & PDF Generationสร้าง API และ React Form สำหรับรับออเดอร์ (รองรับสเปกย่อยหลายรายการใน 1 ออเดอร์)ระบบออกเอกสาร PDF (Quotation ใบเสนอราคา / Delivery Note ใบส่งสินค้า) จาก BackendPhase 4: Production Board, Inventory & Offcutหน้า Kanban Board สำหรับฝ่ายผลิตระบบตัดสต๊อกสองจังหวะ (Reserve -> Actual Deduct) และการนำเศษวัสดุ (Offcut) กลับเข้าคลัง(Optional) ระบบแจ้งเตือนผ่าน LINE/Telegram ในขั้นตอนสุดท้ายคำสั่งเริ่มต้นสำหรับ AI (First Action):เริ่มต้นทำ Phase 1 & Phase 2 โดยการเขียน Database Schema (SQL) ทั้งหมดที่รองรับโครงสร้างข้างต้น พร้อมกับเขียนฟังก์ชันคำนวณราคาใน Golang (pricing_engine.go) ที่รองรับการคิดค่ากระดาษ หมึก % Coverage สันกระดูกงู และค่าบริการคัสตอม
