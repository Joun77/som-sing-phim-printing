Master Prompt: ระบบจัดการโรงพิมพ์ (Printing Shop Management System)Context:ให้คุณรับบทเป็น Expert Full-Stack Developer และ System Architect ช่วยฉันพัฒนาระบบหลังบ้าน (Backend) และระบบแดชบอร์ด (Frontend) สำหรับธุรกิจโรงพิมพ์ โดยเน้นความเสถียร ความปลอดภัยของข้อมูล และกระบวนการผลิตที่ถูกต้องตามมาตรฐานโรงพิมพ์1. Tech StackBackend: Golang (Gin หรือ Fiber Framework)Frontend: React (Vite, React Query สำหรับ State Management, TailwindCSS สำหรับ UI)Database: PostgreSQL หรือ MySQL (ต้องใช้ Relational Database)2. โครงสร้างผู้ใช้งาน (RBAC - Role-Based Access Control)ระบบต้องมี Role พื้นฐานดังนี้:admin: เข้าถึงได้ทุกระบบ (ดูต้นทุน, กำไร, รายงานบัญชี, แก้ไขสูตรคำนวณ)sales: รับออเดอร์, ดูราคาขายลูกค้า (ห้ามเห็นต้นทุน/กำไร)production: ดูคิวงาน, อัปเดตสถานะการผลิต, ดู Link Google Drive (ห้ามเห็นข้อมูลราคาหรือการเงินทุกชนิด)เงื่อนไข: Backend ต้องมี Middleware ตรวจสอบ Role จาก JWT Token ทุกครั้งที่เรียก API3. Workflow ของออเดอร์ (Order Statuses)ออกแบบ Status ของ Order และ Order Items ให้รองรับกระบวนการดังนี้:DRAFT: สร้างออเดอร์ (ยังไม่ยืนยัน)WAITING_DEPOSIT: รอลูกค้าโอนมัดจำPREPRESS_CHECK: ช่างตรวจสอบไฟล์ (ดึงไฟล์จาก Google Drive Link ที่เซลส์แนบไว้)WAITING_APPROVAL: ส่งพรูฟ/ส่งแบบให้ลูกค้ายืนยันREADY_TO_PRINT: ลูกค้ายืนยันแบบแล้ว (จังหวะนี้ระบบจะ Reserve / จองสต๊อกวัตถุดิบ)IN_PRODUCTION: กำลังพิมพ์ / ตัด / เข้าเล่ม (ระบุเครื่องพิมพ์ที่ใช้งาน)COMPLETED: ผลิตเสร็จสิ้น และทำบันทึกของเสีย (Wastage) ตัดสต๊อกจริงDELIVERED: จัดส่งสำเร็จ / รับเงินครบ4. ข้อกำหนดสำคัญด้าน Database & Business Logic (CRITICAL)Pricing Logic MUST be in Backend: การคำนวณราคาทั้งหมด (ค่ากระดาษ, หมึก, ค่าแรง, การเข้าเล่ม) ต้องคำนวณที่ Golang เท่านั้น ห้ามให้ React คำนวณราคาสุทธิเองPricing Snapshot: ในตาราง order_items ต้องบันทึก unit_price, cost_price ณ วันที่สั่งซื้อเสมอ ห้าม Query ราคาจากตารางตั้งต้น (Master Table) แบบ Real-time เพื่อป้องกันบิลเก่าราคาเพี้ยนเมื่อมีการปรับราคาวัตถุดิบInk Coverage Calculation: สูตรคำนวณหมึก ให้รับค่า % การครอบคลุมหน้ากระดาษ (เช่น 5%, 30%, 80%) จากหน้าบ้าน แล้วมาคำนวณจากสเปกหมึกมาตรฐานที่หลังบ้าน (เช่น หมึก 1 เซ็ต 210ml พิมพ์ได้ 6,000 หน้า ที่ 5%)Inventory Transactions: ต้องมีตาราง inventory_transactions เก็บประวัติทุก Action (รับเข้า, เบิกผลิต, เปลี่ยนเป็น Offcut/เศษวัสดุเหลือใช้)Wastage & Offcut: ตอนที่งานสถานะ COMPLETED ต้องมีฟอร์มให้ช่างกรอกว่า "ใช้งานจริงไปเท่าไหร่" (เพื่อหักของเสียตอนตั้งเครื่อง) และมีฟอร์มนำเศษวัสดุ (Offcut) กลับเข้าสต๊อก5. Frontend Requirementsใช้ React Query หรือ SWR สำหรับทำ Data Fetching เพื่อให้สถานะออเดอร์อัปเดตแบบเรียลไทม์หน้าจอของฝ่ายผลิต (production role) ให้แสดงผลเป็นรูปแบบ Kanban Board (ลากวางสถานะได้) เพื่อให้ใช้งานง่ายUI สำหรับแนบไฟล์งาน ให้ทำเป็น Text Input รับค่า URL (Google Drive Link) และแสดงเป็นปุ่ม "เปิดไฟล์งาน" ในฝั่งผลิต6. ลำดับการพัฒนา (Development Phases) ที่ต้องการให้ AI ทำให้ AI ช่วยพัฒนาตามลำดับดังต่อไปนี้ โดยฉันจะสั่งงานทีละ Phase:Phase 1: Database Schema & Auth. ออกแบบ SQL Schema ทั้งหมด (Users, Materials, Orders, Inventory) และทำระบบ Login/JWT MiddlewarePhase 2: Product & Pricing Engine. เขียน API (Golang) สร้างสูตรคำนวณต้นทุน/ราคาขาย (กระดาษ, หมึก, เข้าเล่มกระดูกงู)Phase 3: Order Management. ทำ API และ React Component สำหรับสร้างออเดอร์ และระบบมัดจำPhase 4: Production Board & Inventory. ทำ Kanban Board ฝั่งหน้าบ้าน, ระบบตัดสต๊อกด้วย SQL Transaction, และระบบเพิ่ม Offcut กลับเข้าคลังคำสั่งเริ่มต้นสำหรับ AI (First Action):โปรดอ่านข้อกำหนดทั้งหมดนี้ และเริ่มต้น Phase 1 โดยการเขียน Database Schema (SQL) ที่เหมาะสมกับระบบนี้ พร้อมอธิบายว่าแต่ละ Table ทำหน้าที่อะไร และรองรับข้อกำหนดที่ให้ไว้อย่างไร
