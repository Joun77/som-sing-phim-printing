📌 System Improvement & Technical Specification BlueprintProject: Som Sing Phim Printing System (ສົມສິ່ງພິມ)Target Stack: Go (Backend) + PostgreSQL (Database) + React & TypeScript (Admin & Customer Frontends)1. Database Schema & Architecture Enhancements1.1 Ink Baseline & Comparison ModelGenuine Inks (genuine_inks): เก็บสเปกและปริมาณน้ำหมึกแท้ที่เป็นมาตรฐาน (Baseline Volume in ml, Standard Page Yield) เพื่อใช้เป็นเกณฑ์เปรียบเทียบCompatible Inks (compatible_inks): เก็บข้อมูลหมึกเทียบ/หมึกนำเข้า (Imported Volume in ml, Cost per Unit) พร้อมผูก FOREIGN KEY ไปยัง genuine_inks เพื่อใช้วิเคราะห์ต้นทุนจริงต่อมิลลิลิตร (Cost per ml)1.2 Database Operations & SecurityMigration Tooling: ใช้ golang-migrate หรือ goose ในการจัดการ Versioning ของ Database Migrations (.sql) เพื่อความเสถียรในการทำงานร่วมกันAudit Logs: เพิ่มตาราง audit_logs สำหรับฝั่ง Admin เพื่อบันทึกประวัติการปรับแก้ไขสต็อกน้ำหมึก ราคา และสเปกเครื่องพิมพ์Timezone Standardization: กำหนดคอลัมน์ประเภทวันเวลาทั้งหมดให้เป็น TIMESTAMPTZ (Timestamp with time zone)2. Backend Logic Improvements (Go - admin-system/backend/)2.1 API & AuthenticationAdmin Endpoints Security: Enforce JWT Authentication สำหรับทุก API ภายใต้ /api/admin/*Customer API Isolation: แยก Public/Customer API สำหรับสร้างออเดอร์/ส่งไฟล์ และเช็คสถานะงานโดยไม่ต้องเข้าถึงสเปกน้ำหมึกเชิงลึก2.2 Yield & Cost Analytics Engineพัฒนา Logic การคำนวณคาดการณ์จำนวนแผ่นงานพิมพ์ (Yield Estimation) โดยเปรียบเทียบปริมาณ ml ของหมึกเทียบกับ Baseline หมึกแท้สร้างระบบคำนวณสถิติประหยัดต้นทุน (Cost Savings Analytics) สำหรับแสดงรายงานหลังบ้าน3. Admin System Improvements (admin-system/frontend/)3.1 Dashboard & PerformanceLow Stock Alerts: เพิ่ม Widget แจ้งเตือนเมื่อหมึก/กระดาษในสต็อกต่ำกว่าเกณฑ์Optimized Queries: ใช้ Pagination และ Aggregation Query ใน Go เพื่อหลีกเลี่ยงการดึงข้อมูลทั้งหมดมาประมวลผลที่ Client3.2 Inventory & Lot ManagementFIFO Lot Tracking: รองรับการบันทึกหมายเลขล็อต (Lot Number) และวันหมดอายุของหมึก เพื่อรองรับระบบนำหมึกเก่ามาใช้ก่อน3.3 Order & Production ManagementOrder Status Workflow: ระบบสถานะงานแบบ Kanban Board (Pending -> Quotation Approved -> Printing -> Completed -> Delivered)Quotation Submission: เพิ่มฟังก์ชันให้ Admin สามารถตรวจสอบไฟล์งานและกรอกราคาประเมิน (Submit Price) กลับไปยังลูกค้า4. Customer Service System Improvements (customer-service/)4.1 Order Submission (RFQ Pattern)Strict Boundary Rule: ห้าม ทำระบบคำนวณราคาแบบเรียลไทม์ฝั่งลูกค้า (No Client-side Real-time Dynamic Print Cost Preview) เพื่อป้องกันข้อผิดพลาดในการประเมินราคาRequest for Quotation (RFQ) Flow: ลูกค้าอัปโหลดไฟล์งาน เลือกรุ่น/ชนิดกระดาษ จำนวน และความต้องการ แล้วกด "ส่งออเดอร์เพื่อขอใบเสนอราคา" จากนั้นระบบจะสร้าง Order ID ให้ลูกค้าทันที4.2 Order Trackingระบบค้นหาออเดอร์ด้วย Order ID หรือ เบอร์โทรศัพท์ เพื่อแสดงสถานะงาน (เช่น รอประเมินราคา -> ยืนยันชำระเงิน -> กำลังพิมพ์ -> พร้อมรับสินค้า)5. Development Guidelines for Antigravity AI AgentLinting & Quality: ตรวจสอบโค้ด TypeScript ด้วย .oxlintrc.json เสมอContainerization: รักษาโครงสร้าง Dockerfile และ docker-compose.yml ให้พร้อมรันทั้งระบบ Admin และ Customer ServiceAgent Rules: อ้างอิงข้อกำหนดในโฟลเดอร์ .agents/rules/ ในทุกการสร้างหรือแก้ไขไฟล์
